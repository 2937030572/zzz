## 写操作 3-4 秒延迟排查与优化

用户反馈：添加入金 / 删除记录都要 3-4 秒。

### 根因

不是代码慢，是**串行数据库往返次数 × 跨境延迟**：

- 添加入金（优化前）：插入(1) → 重算查出入金+交易并行(1) → 查快照(1) → 写快照(1) → 前端全量刷新(1)
  = **5 个串行往返**；删除记录 6 个（多一次查行）。
- 本机/服务器在中国 → Supabase 海外节点，每次往返 600-800ms，5 次正好 3-4 秒。

### 优化（已实施）

1. `assets/migrations/002_recalc_balance_rpc.sql`（新增）：Postgres 函数 `recalc_balance(p_account_id)`，
   数据库内一次完成重算 + upsert 快照。**需用户在 Supabase SQL Editor 执行**。
   函数口径与 accountScope 一致（默认账户含 null account_id），依赖 001 的唯一索引。
2. `src/lib/balance.ts`：
   - `recalcAndPersistBalance` 优先 RPC（PGRST202 = 函数未注册则回退旧 JS 路径，其他错误抛出）；
   - `syncBalanceSnapshot` 改 upsert（42P10 = 无唯一索引则回退「查后写」）。
3. 效果：添加入金 5 RT → 3 RT（插入 + RPC + 前端刷新），预计 3-4s → ~1.5-2s。
   全部带降级，迁移不跑功能也不坏。

`tsc` EXIT=0、`eslint` EXIT=0。沙箱无法连 Supabase，实际延迟改善需用户跑迁移后实测。
