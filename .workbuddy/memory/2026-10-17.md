## 修复：hover 浮出操作按钮「看不见」（用户反馈仍不生效）

### 根因（两个叠加，都是布局/CSS 层，不是 JS 逻辑）
1. **列宽溢出把操作列顶出可视区**（主因）
   - `main` 是 `max-w-5xl`(1024) + `px-6`(48)，`CardContent` 又是 `px-6`(48) → 表格可用宽 **928px**
   - 但 `Table` 是 `min-w-[1020px]`，列宽合计正好 1020 → 横向溢出 92px
   - 操作列在最后（x 920–1020），可视区只到 928 → **只露出 8px，按钮等于完全不可见**
   - 修：列宽重排为合计 **896px**（116/98/128/134/54/84/84/90/108），`min-w-[880px]`；
     操作列再 `sticky right-0 bg-card group-hover:bg-muted`，窄窗口横向滚动时仍常驻右侧
2. **Tailwind v4 给 `hover:` / `group-hover:` 自动套 `@media (hover: hover)`**
   - 实测编译产物：`.sm\:group-hover\:opacity-100{@media(width>=40rem){&:is(:where(.group):hover *){@media(hover:hover){opacity:100%}}}}`
   - 触摸优先的设备（触屏笔记本/平板模式/设备模拟）该查询为 false → 悬停样式**永不生效**，按钮彻底藏死
   - 修：`globals.css` 手写 `.row-actions`（默认 opacity 0）+
     `@media (hover:hover){.row-hover:hover .row-actions{opacity:1}}` +
     `@media (hover:none){.row-actions{opacity:1}}`，两条路都不会把功能藏死
   - **结论：本项目凡是需要 hover 才出现的可交互元素，不要用 Tailwind 的 `hover:` 变体，用手写 CSS + `hover:none` 兜底**

### 其他修复
- `TradeTable` 整行 `cursor-pointer` + `onClick` 打开详情（只读，非破坏性），
  用 `window.getSelection()` 判空避免复制品种文本时误触发；三个按钮全部 `e.stopPropagation()`
- `ui/dialog.tsx` 内联 `style` 里的 `maxHeight:'90vh'` 会**静默覆盖**调用方传的 `max-h-[86vh]`
  （已移除该内联项，交给 className 控制）—— 内联样式优先级高于类，共享组件里不要写死尺寸

### 排查手法（可复用）
- 用 `@tailwindcss/postcss` + postcss 在 node 里直接编译 `app/globals.css`，grep 产物确认
  某个变体到底生成了什么（`@media (hover:hover)` 就是这样被抓出来的）
- 用 `tailwind-merge` + `clsx` 打印 `cn()` 的最终类名，确认类有没有被误合并掉
  （实测：`overflow-hidden` 与 `overflow-y-auto` 不冲突，且 `overflow-y-auto` 在产物中靠后 → 弹窗可滚动）
